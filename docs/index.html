Referência de uso da API

Este documento descreve as rotas que o CelcoinHomolog simula. Use-o como referência durante a integração: cada endpoint traz método, path, propósito, shape do request e da resposta, webhook disparado (quando aplicável) e os cenários de erro que você pode acionar de forma determinística.

O ambiente não conversa com a Celcoin real — todas as respostas são geradas localmente. Catálogo bruto de rotas: docs/endpoints.md (fonte da verdade: app/web.php). Cenários de teste: docs/scenarios.md.

Como rodar

Stack: PHP puro sobre microframework próprio (App\Core\*), persistência em SQLite (app/tmp/cslabs/cslabs.sqlite), sem dependências de runtime.

  • Servir o diretório raiz como DocumentRoot com Apache + .htaccess (rewriting tudo para index.php).
  • Servidor embutido (php -S) não roteia sozinho — precisa de Apache (ou nginx replicando a regra).
  • Timezone fixado em America/Sao_Paulo. DEV=true em app/config.php liga display_errors.
  • Logs: app/tmp/errors.log.
  • Painel de inspeção de chamadas: /shots/<clientId>/ (mostra request/response capturados).

Autenticação

Toda chamada autenticada usa o access token obtido em POST /v5/token no header Authorization: Bearer <token>. O mock aceita qualquer client_id/client_secret e emite um token persistido localmente (visível no painel /shots).

POST /v5/token

Gerar token de acesso OAuth 2.0 (client_credentials).

Body

{ "client_id": "...", "client_secret": "...", "grant_type": "client_credentials" }

Response 200

{ "access_token": "...", "token_type": "bearer", "expires_in": 3600 }
CSLAB400 se payload inválido

Cenários de teste (magic values)

1. Magic amount — em qualquer endpoint transacional, mande amount abaixo de R$ 1,00 para disparar um cenário pré-definido. Valores ≥ R$ 1,00 seguem o fluxo normal.

2. Convenção da chave PIX — para endpoints sem amount (DICT, onboarding, account/check), trechos na chave PIX disparam cenário: erro@/error@/500@ → error · falha@/failed@ → failed · fraude@/fraud@/suspeita@ → fraud · 404@/notfound@/inexistente@ → not_found · bloqueado@/blocked@ → blocked.

Webhooks (visão geral)

Após cada operação assíncrona, o mock dispara um webhook para a URL registrada em POST /baas-webhookmanager/v1/webhook/subscription para a respectiva entity. A entrega acontece fora do lifecycle da request via worker spawnado por exec — funciona em qualquer SAPI (php -S, mod_php, FPM).

Envelope padrão:

{
  "id": "wh_…",
  "webhookId": "<subscriptionId>",
  "entity": "pix-payment-out",
  "createTimeStamp": "2026-05-28T14:32:11-03:00",
  "status": "CONFIRMED",
  "body": { … payload específico … }
}

O campo do timestamp varia: createTimeStamp (S maiúsculo) para pix-payment-out, pix-payment-in, spb-transfer-in, spb-reversal-in, spb-reversal-out; createTimestamp (s minúsculo) para os demais.

Entidades mapeadas: pix-payment-out, pix-reversal-out, spb-transfer-out, internal-transfer-out, billpayment, charge-create, onboarding-create, onboarding-proposal, kyc, account-status, launch-debit, launch-credit.

Dispatch manual (debug): POST /cslabs/webhook/dispatch com {entity, status?, body?, delaySeconds?}.
